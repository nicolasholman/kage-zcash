Every payment is shielded. Amount, sender and the API it paid for stay off the public chain.

The merchant holds no spend key. Its facilitator finds the payment with an incoming viewing key, which can't see the merchant's own spends or change, and signs a receipt.

The x402 flow, shielded

The challenge names the price and a single-use memo nonce. The payment carries the nonce in its encrypted memo.

Incoming viewing key only

The facilitator trial-decrypts the transaction with the merchant's incoming viewing key, checks recipient, amount, memo and the mined block's time, then signs an ed25519 receipt.

Frequently asked questions

Straight answers about privacy, keys and limits.

What does the chain see?

A shielded transaction. The amount, the memo with the nonce and the parties are encrypted; only the merchant's viewing key can read its side.

What still leaks?

The merchant sees the client's IP (plain HTTP), the lightwalletd operator sees which txid is looked up and when, and the agent's local ledger is plaintext JSON. Timing between the 402 and the next block can also link them.

Can the merchant spend my money?

No. The facilitator holds the merchant's incoming viewing key only. It can see incoming payments, never move funds, and never see the merchant's own spends.

What stops an agent overspending?

spendguard runs before a transaction is built: a daily cap, a host allowlist and an approval threshold. A refusal exits with code 3 and nothing is broadcast.

Is it live?

On Zcash testnet, with the paid transaction linked above. Every decision is written to the agent's ledger and shown on the dashboard. Not audited.
